What virtualisation does

Use software to create multiple virtual systems on shared hardware

Virtualisation uses software to simulate hardware functionality and create virtual computer systems.

This allows an organisation to run more than one virtual system—and multiple operating systems and applications—on a single physical server.

The result is more efficient use of computing resources, reduced dependence on separate physical machines and a more flexible infrastructure that can be managed around business requirements.

More value from existing resources

Physical servers are often capable of supporting more work than a single application or operating system requires.

Virtualisation allows that available capacity to be divided and used more effectively while keeping systems logically separated.

Server consolidation

Reduce infrastructure sprawl without reducing capability

Virtualisation is closely connected with server consolidation. Multiple workloads can share physical infrastructure while remaining organised as separate virtual systems.

Reassessing the traditional model

On-premises servers have supported business networks for decades

Traditional client-server networks normally use a physical server on site to provide core functions such as authentication, file and printer sharing, group policies and access to shared business applications.

This approach remains familiar, but it also creates ongoing responsibilities for hardware, storage, malware protection, vulnerability management, access control and regular patching.

As servers age or reach capacity, organisations must fund upgrades, replacement and additional storage. Hardware failure can also create outages that interrupt work and reduce productivity.

The question for modern organisations

Is maintaining business-critical services on local hardware still the most suitable approach when cloud platforms can provide identity, storage, collaboration, management and computing resources as online services?

The right answer depends on the organisation, its systems and its operational requirements.

Why licence management matters

Every software installation creates an obligation

When an organisation purchases software, it enters into a licence agreement with the provider when the software is installed or first accessed.

Those agreements define who may use the software, where it may be installed and how it may be deployed. As organisations add more applications across departments, devices, distributed networks and cloud environments, keeping track of those obligations becomes increasingly difficult.

An active software licence management programme helps reduce the risk of accidental non-compliance while giving the organisation a clearer view of what it owns, what it uses and what it is paying for.

The challenge

Software licensing rarely sits in one place. It can be spread across individual users, desktop computers, servers, mobile devices, cloud subscriptions and hybrid environments.

Without active oversight, organisations can easily lose track of renewals, usage rights, unused licences and contractual restrictions.

Licensing models

Different software requires different controls

There is no single licensing model. The correct approach depends on how the software is purchased, deployed and used across the organisation.

01

User licences

The software is licensed for use by a specific person, often across one or more approved devices.

02

Device licences

The software is licensed for installation or use on a particular machine, regardless of who uses it.

03

Cloud and hybrid licences

Subscription rights must be managed across cloud platforms, on-premise systems and mixed working environments.
